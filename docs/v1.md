AI 绘本朗读 App 需求文档 V1
1. 项目概述
1.1 项目名称
AI 绘本朗读 App（暂定）

1.2 产品定位
一个纯本地、单用户的绘本朗读工具。
用户导入绘本的扫描件或照片（单页单图），通过配置自己的多模态模型与 TTS 服务，在本地生成绘本文本与朗读音频，并支持连续播放和重复播放。

1.3 产品目标
帮助用户将绘本图片快速转化为可播放的音频内容
支持本地持久化保存文本和音频
支持多绘本管理与多页连续播放
支持中文、英文绘本
支持用户自行配置兼容 OpenAI 格式的模型接口
1.4 目标用户
有亲子阅读需求的个人用户
希望将绘本图片整理为可听内容的用户
有自己模型 API Key 的进阶用户

3. 产品约束与原则
3.1 使用模式
App 为单用户纯本地使用
所有绘本数据、图片、文本、音频默认保存在本地
3.2 模型调用方式
App 直接调用用户配置的模型接口
默认兼容 OpenAI 风格 API
用户自行填写 API Key 与 Base URL
可兼容部分第三方供应商，只要接口格式兼容
3.3 任务触发方式
所有识别与语音生成均需用户主动点击触发
不进行自动后台生成
3.4 文件处理方式
单页对应单张图片
音频按页生成并本地保存
重新生成时覆盖旧文件
4. 用户故事
4.1 创建绘本
作为用户，我希望创建一本绘本并导入多张页面图片，以便后续逐页生成朗读内容。

4.2 内容生成
作为用户，我希望点击按钮后生成页面原文、画面描述和朗读文本，以便检查和编辑。

4.3 语音生成
作为用户，我希望把页面朗读文本合成为语音并保存下来，以便重复播放。

4.4 连续播放
作为用户，我希望整本绘本按页连续播放，以便孩子顺畅听完整本书。

4.5 文本修正
作为用户，我希望手动修正原文、画面描述和朗读文本，并重新生成音频，以提高质量。

4.6 模型配置
作为用户，我希望针对中文和英文分别配置默认模型和 TTS，以适配不同绘本。

5. 核心业务流程
5.1 新建绘本流程
用户点击“新建绘本”
输入或修改绘本名称
选择绘本语言：
中文
英文
导入多张页面图片
调整页面顺序
保存绘本
5.2 页面生成流程
用户进入绘本详情页
选择“生成整本”或“生成当前页”
系统按页调用多模态模型
为每页生成：
原文文本
画面描述
朗读文本
生成成功后更新页面状态
5.3 音频生成流程
页面已有朗读文本
用户点击“生成语音”或“整本生成语音”
系统按页调用 TTS
生成音频并保存本地
若已有旧音频，则覆盖
5.4 播放流程
用户打开绘本详情或播放页
点击某页播放，或点击“连续播放”
播放当前页音频
若开启连续播放，自动切换到下一页
记录当前播放页
5.5 编辑与重生成流程
用户进入页面详情
查看并编辑：
原文文本
画面描述
朗读文本
保存文本修改
点击“重新生成语音”
新音频覆盖旧音频

6.4 页面内容生成
功能描述
根据页面图片调用多模态模型生成页面文本内容。

页面文本结构
每页包含以下三个可编辑字段：

1）原文文本
从页面中尽量忠实提取出的文字内容
2）画面描述
对页面插图中的角色、场景、动作、情绪等内容的补充说明
可为空
3）朗读文本
用于实际 TTS 的最终朗读内容
可基于原文文本和画面描述整合生成
应更加自然、适合儿童听读
生成方式
支持单页生成
支持整本逐页生成
生成失败时仅影响当前页
用户可重试失败页
编辑能力
原文文本可编辑
画面描述可编辑
朗读文本可编辑

8. 非功能需求
8.1 本地优先
所有数据默认保存在本地
无需联网也可浏览已保存内容和播放本地音频
模型调用时需要网络连接
8.2 性能
绘本列表应快速加载
单页文本与音频生成状态应即时反馈
连续播放切页时不应明显卡顿
8.3 容错
单页生成失败不影响其他页
可随时重试
App 重启后保留本地数据和状态
8.4 安全
API Key 本地存储需尽量安全
不记录和上传用户内容到自有服务器
不在日志中明文输出用户 Key

四、这个方案下，RN 技术上建议补什么
既然你要纯本地，我建议技术架构也尽量简单稳一点。

1. 本地数据库
建议选一个：

SQLite
稳
适合结构化数据
最适合 Book/Page/Config 这种关系数据
或 WatermelonDB
更偏复杂场景
或 Realm
开发体验不错，但有一定绑定感
我个人建议你这个项目：
直接 SQLite 就够了。

2. 本地文件存储
你会存：

原图
生成音频
建议：

图片和音频都复制到 app 私有目录
数据库只存路径
删除绘本时一起清理文件
RN 可用：

react-native-fs
3. 音频播放
建议：

如果是裸 RN：react-native-track-player
如果是 Expo：expo-av
如果你要支持后台播放、锁屏控制，react-native-track-player 更强。

4. 图片选择
react-native-image-picker
如果要拖拽排序：

react-native-draggable-flatlist
5. 密钥存储
因为是用户自己填 API key，建议不要存在普通 AsyncStorage。

可考虑：

react-native-keychain
或系统安全存储封装
模型配置中的非敏感信息可放数据库，API key 放安全存储。

6. 模型调用抽象
虽然是本地 app，但代码里一定要做抽象层，不然后面支持第三方会很乱。

建议分成：

VisionProvider
TTSProvider
统一接口例如：

generatePageContent(image, language, options)
generateSpeech(text, voice, speed, options)
这样后面接 OpenAI、OpenRouter、其他兼容供应商会非常容易。
